# 第三章 M1：请假、加班与审批

## 本轮来源说明

这一轮不是用录制用的 Codex CLI 会话执行的，而是课程作者在 Cursor 工作区里亲手跑通一遍项目时产生的真实开发过程。

- 执行方式：在 Cursor 中用编码 Agent 完成编码与自测。
- 记录的 Prompt 是这一轮的**真实任务说明**，不是提前写好的录制版话术。
- 录制版 Prompt 会在真正开录之前，从这份真实记录里重新提炼，不反向编造。

## 本轮任务说明（真实）

```text
用现在项目里的代码和 UI，先把课程案例整个项目自己跑完一遍，逐字稿以后再写。
不要先写讲稿，优先把可运行的案例做出来。
本轮先做第三章的产物：请假、加班和审批流转。
```

## 本轮执行边界

- 新增请假、加班两个模块的完整链路：申请、列表、详情、审批通过、驳回。
- 把员工删除从物理删除改成逻辑离职，并给 `employees` 表补 `status` 和 `phone` 字段。
- 前端增加请假管理、加班管理两个面板和对应弹窗，能在页面上跑通申请与审批。
- 不实现日考勤核算、异常生成、申诉和月报，那些属于第七章。
- 不引入 ORM、前端框架和新的第三方依赖。

## 保留的项目规范（来自 course/agents-md-draft.md）

- 三层结构：`routes/` 接收请求、`services/` 写业务和 SQL、`models/` 只做序列化。
- 路由层禁止直接写 SQL。
- 统一响应 `{"code": 200, "message": "...", "data": ...}`，错误码 400 / 404 / 500。
- 所有代码加中文注释，函数名 `snake_case`，每行不超过 120 字符。
- 数据库默认 `checkin.db`，测试用 `CHECKIN_DB_PATH` 切换。
- 业务异常统一用 `ServiceError`，由全局异常处理器转成标准响应。
