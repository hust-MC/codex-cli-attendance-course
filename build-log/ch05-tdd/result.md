# 第五章：五阶提示词与 TDD

## 本轮实际做的事

1. 建立单元测试基础设施：`tests/base.py` 提供隔离的临时数据库和公共造数方法。
2. 补齐五个测试文件，共 77 个用例，覆盖员工、打卡、请假、加班四个模块和接口层契约。
3. 编写 `scripts/verify.sh` 一键验收脚本，串起静态检查、单元测试、接口冒烟、页面可达性。
4. 用「探索测试」找出两个问题，其中一个是我误判的，一个是真 Bug。
5. 对真 Bug 完整走了一遍从红到绿的修复流程。

## 找到的 Bug

### 真 Bug：审批时不做冲突复查（已修复）

**现象**：员工可以提交两条时间重叠的请假，两条都是 pending，都能提交成功。
主管先审批通过第一条，再审批通过第二条时，系统不报错。
最终数据库里出现两条时间重叠的已审批请假。

**为什么没被发现**：
- 提交时的冲突校验是对的，它只查 `status = 'approved'` 的记录。
- 但两条申请在提交那一刻都还是 pending，谁都不构成冲突。
- 审批环节没有重新检查，所以第一条变成 approved 之后，第二条就畅通无阻了。

**影响**：考勤核算时，同一天的请假会被减两次，工作日天数算少。

**修复**：在 `_review_leave` 里，目标是 `approved` 时先用同一套重叠条件查一次，
排除当前这条自身，命中就抛业务错误。

**测试**：`test_approve_leave_conflict_with_approved_blocked`（回归用例）、
`test_approve_leave_conflict_free_ok`（反向用例，防止改过头）。

### 假 Bug：请假首尾相接被判为冲突（是我的误判，代码是对的）

我一开始以为「已审批 11-18 到 11-20，新申请 11-20 到 11-22」不该算冲突，
因为直觉上两段区间没有交叠。

实际上请假天数含首尾两天，11-20 这天被两段都算上了，是真冲突。原代码判对了。

**这个误判本身有价值**，它说明：
- 写测试前必须先想清楚业务规则，不能凭直觉。
- 「测试红了」有两种可能：代码有 Bug，或者测试写错了。
- 我改了 SQL 但测试还是红的，这才暴露出是我错了。
  如果当时直接改测试预期蒙混过去，就会把一条真实的边界规则改错。

代码最终没改，SQL 保持原样，只补了三个边界用例把这个规则固定下来。

## 五阶提示词

| 阶段 | 作用 | 本轮实例 |
|---|---|---|
| 澄清 | 把模糊需求变成明确问题 | 明确要写什么测试、覆盖哪些分支 |
| 设计 | 先想清楚方案再动手 | 决定用公共基类而不是每个测试造自己的数据 |
| 测试 | 先写会失败的测试 | 探索测试 + 回归用例 |
| 实现 | 让 AI 按测试写实现 | 最小修复，只改 `_review_leave` |
| 评审 | 检查有没有引入回归 | 全量 77 个测试 + 两个边界用例 |

关键纪律写在 Prompt 里：
- 「本轮只写测试，发现 Bug 写失败测试就停下来，不要自己改实现」
- 「只分析，不要修改任何代码」
- 「不要顺手改测试的断言」

## 验证方式

```bash
python3 -m unittest discover -s tests -v   # 77 个用例
bash scripts/verify.sh                      # 一键验收
```

`verify.sh` 依次跑五组检查：语法编译、代码风格、单元测试、接口冒烟、页面可达性。
任何一项失败立即退出，退出码非 0。

## 修复 verify.sh 的两个问题

1. **页面检查写死了旧路径**。前端静态资源已经从 `static/style.css` 挪到
   `static/css/app.css`，脚本里硬编码的 `/style.css` 返回 404。
   改成从 `templates/index.html` 自动提取 `url_for('static', ...)` 的真实路径，
   以后前端改目录不用动脚本。

2. **`find ... -exec awk` 的多文件问题**。行宽检查改成一次性传入所有文件，
   避免 `awk` 在多文件下 `FNR` 语义变化导致的误报。

## 当前限制

- 测试只覆盖到第五章的四个模块，第七章的核算、异常、申诉还没有测试。
- 单元测试用 `unittest` 的临时数据库，跑得比接口冒烟快，但覆盖的是 service 层，
  HTTP 层的完整链路仍靠 `scripts/smoke-api.sh` 兜底。
- 探索测试文件 `test_bug_exploration.py` 是找 Bug 用的，不是回归测试，
  后续可以清理或改造成正式用例。
