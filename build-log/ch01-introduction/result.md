# 第一章：认知与成品演示

本章不写业务代码，只确定讲什么、做什么、不做什么。

## 本轮实际做的事

- 确定项目名称「指尖打卡 2.0：考勤异常闭环平台」和它的定位。
- 确定两个用户角色：员工和主管，以及各自的职责边界。
- 画出核心业务流程：打卡 → 日核算 → 异常 → 申诉 → 审批 → 月报。
- 确定数据模型七张表和 API 模块划分。
- 确定默认考勤规则：09:00 上班、18:00 下班、迟到早退各 5 分钟宽限、周一至周五。
- 确定异常状态机：`open → appealed → approved / rejected`。
- 写死固定演示数据和六步演示动作，保证录制时结果不漂移。
- 列出六条明确不做的事情。

## 本章真实偏差

**演示脚本要等到第七章才能真跑。**

本章计划里写的是「录制最终成品预览」，但完整成品（核算、异常、申诉、月报）要到第七章才做完。

处理方式有两种：

1. 提前把全部功能做完再录第一章——课程顺序就废了。
2. 第一章用「效果预告」的形式：讲清楚系统最终长什么样、解决什么问题，不承诺当场能点。

目前按第二种准备，但**这一段没有录过，还没有验证过效果**，属于待确认项。

## 录课时可以抛给学生的问题

- 一个员工从来没有打卡，也没有请假，系统该怎么判定？
- 请假被驳回之后，员工当天缺勤的异常还会生成吗？
- 如果主管出差三天没人审批，异常就一直挂着，这个流程合理吗？
