# 十章阶段任务与录制节点

> 本文件使用“第一章”“第二章”这样的实际章节名称，不使用 `S02`、`S03` 等内部阶段编号。
> `build-log/` 目录统一使用 `chNN-描述` 命名，并与章节编号一一对应。

## 使用规则

- 从第二章开始，每一章先由用户确认本轮任务 Prompt，再开始写代码。
- 每章只做本章任务，不提前实现后续章节功能。
- 每章结束时必须可运行、可验收，并更新 `build-log/`。
- 章节完成后先做一次复盘，确认下一章 Prompt 后才继续。
- 本文中的“Prompt 记录点”不是预先写好的录制版 Prompt，而是本章开发过程中值得保存的位置。
- 真实报错、无效尝试和修复 Prompt 必须原样保留，不能只保留最终成功版本。

| 第二章 环境与最小可跑版 | 50 分钟 | 从空目录跑通最小闭环 | Flask 骨架、员工、打卡 | 可创建员工并签到签出 |

| 第四章 AGENTS 与上下文 | 40 分钟 | 建立项目级规范 | AGENTS.md、目录和上下文规范 | 长 Prompt 与短 Prompt 对比 |

## 第一章：认知与成品演示

### 本章目标

先让学员看到最终价值，再解释为什么用一个考勤异常闭环项目贯穿课程。

### 本章任务

1. 确定项目名称、角色和核心业务流程。
2. 固定最终演示脚本：正常、迟到早退、缺卡、请假、缺勤、申诉和审批。
3. 编写 PRD 和验收标准，明确不做的范围。
4. 录制最终成品预览，不实现业务代码。
5. 解释课程三个闭环：业务闭环、质量闭环、Agent 闭环。

### 本章产物

- `course/project-brief.md` 的需求和范围部分。
- 最终演示脚本。
- 第一版验收清单。

### 建议记录的 Prompt 节点

- 需求澄清 Prompt：把口头需求整理成角色、流程和验收标准。
- 范围收敛 Prompt：把工资、人脸、复杂排班等非目标排除。

### 建议记录的 Bug 或偏差

- 本章一般没有代码 Bug。
- 重点记录“需求写得太大”或“演示流程不闭环”的修正过程。

### 本章验收

- 能用 3 分钟讲清最终系统如何完成一次异常闭环。
- 能列出至少 5 条明确不做的事情。

## 第二章：环境与最小可跑版

### 本章目标

从空目录建立一个真的能运行的 Flask + SQLite 项目，并完成员工与打卡的最小业务闭环。

### 本章任务

1. 检查 Codex CLI、Python、Flask 和 SQLite 环境。
2. 创建应用入口、数据库初始化、路由、服务和测试目录。
3. 建立员工和打卡两张表。
4. 实现员工新增、列表、详情、修改和逻辑离职。
5. 实现上班签到、下班签出和当天记录查询。
6. 完成一个最小页面，可以创建员工并完成签到签出。
7. 编写健康检查、员工和打卡测试。

### 本章产物

- `app.py`、`db.py`、`requirements.txt`。
- `models/employee.py`、`models/checkin.py`。
- `services/employee_service.py`、`services/checkin_service.py`。
- `routes/employees.py`、`routes/checkins.py`。
- 最小首页和打卡页面。
- `scripts/smoke-api.sh` 接口冒烟脚本。
- 第一版 Git 基线，供后续阶段快照和重构使用。
- `build-log/` 下本章完整开发记录。

### 建议记录的 Prompt 节点

- 空目录初始化 Prompt。
- 数据库建表 Prompt。
- 员工与打卡模块生成 Prompt。
- 重复签到、未签到先签出、离职员工打卡的修复 Prompt。

### 建议记录的 Bug 或偏差

- 日期和时区处理错误。
- 重复打卡没有被拦截。
- 路由层直接写 SQL，违反分层。
- 测试污染正式数据库。

### 本章验收

- `python3 app.py` 可以启动。
- `bash scripts/smoke-api.sh` 全部通过（单元测试挪到第五章，原因见第三章偏差说明）。
- 可以创建员工并完成一次签到签出。
- 重复签到返回业务错误。

## 第三章：Agent 批量开发

### 本章目标

演示如何让 Codex 一次扩展一个完整业务模块，同时用测试约束生成结果。

### 本章任务

1. 实现请假申请、列表、详情、审批通过和驳回。
2. 实现加班申请、列表、详情、审批通过和驳回。
3. 校验开始结束日期、请假冲突、加班时长和审批状态。
4. 批量生成两个模块的测试。
5. 增加请假和加班的页面入口。
6. 处理 Agent 生成偏差和回归问题。

> 偏差说明：第 4 条的单元测试实际挪到了第五章，和 `tests/` 目录一起建。
> 原因是 `AGENTS.md` 规范里提到的 `tests/` 目录当时还不存在，
> 模型会绕过一个仓库里不存在的目标而不是替你补齐，详见 `build-log/ch04-agents-md/short-prompt-verify.md`。
> 本章改用 `scripts/smoke-api.sh` 做接口层验收，32 项断言覆盖两个模块的正常流程和非法流转。

### 本章产物

- `services/leave_service.py`、`services/overtime_service.py`。
- `routes/leaves.py`、`routes/overtimes.py`。
- 请假和加班页面。
- 对应测试和 `build-log/` 记录。

### 建议记录的 Prompt 节点

- 一次生成请假和加班模块的 Prompt。
- 批量生成测试的 Prompt。
- 发现生成代码重复或漏校验后的修复 Prompt。

### 建议记录的 Bug 或偏差

- 请假日期区间处理错误。
- 已审批记录被重复审批。
- 列表接口返回裸数组，不符合统一格式。
- 出现路由直接查库或业务逻辑写进前端。

### 本章验收

- 员工可以提交请假和加班。
- 主管可以审批通过和驳回。
- 非法状态流转返回 400。
- 两个模块的接口断言全部通过（`bash scripts/smoke-api.sh`）。

## 第四章：AGENTS.md 与上下文治理

### 本章目标

把重复出现的工程规则从任务 Prompt 中抽离出来，形成项目级上下文。

### 本章任务

1. 找出前几章重复声明的技术、目录、API 和测试规则。
2. 编写项目根目录 `AGENTS.md`。
3. 对比无规范长 Prompt 和有规范短 Prompt。
4. 调整目录职责和接口约定，让后续模块可以复用。
5. 用一条短 Prompt 验证 Agent 是否真的遵循规范。

### 本章产物

- 根目录 `AGENTS.md`。
- `course/agents-md-and-prompt.md`。
- 长 Prompt 与短 Prompt 对比材料。
- 一次遵循规范的实际开发记录。

### 建议记录的 Prompt 节点

- 从已有代码反推项目规范的 Prompt。
- 生成 AGENTS.md 的 Prompt。
- 评审并补充 AGENTS.md 的 Prompt。
- 使用短 Prompt 执行任务的对照记录。

### 建议记录的 Bug 或偏差

- 规则写得过宽，导致后续实现被错误限制。
- 规则与真实代码不一致。
- Prompt 已经写了规范，但 AGENTS.md 中没有对应约束。

### 本章验收

- 新任务 Prompt 不需要重复技术栈、目录和响应格式。
- AGENTS.md 的每条关键规则都能在代码或测试中找到落点。
- 用一条短 Prompt 跑通真实开发，模型 8 条规则全部遵守，记录见 `build-log/ch04-agents-md/short-prompt-verify.md`。

## 第五章：五阶提示词与 TDD

### 本章目标

演示如何把“让 AI 写功能”变成“先定义问题，再让 AI 用测试证明实现正确”。

### 本章任务

1. 选一个真实问题：例如日期边界、重复打卡或异常状态非法流转。
2. 先写复现步骤和失败测试。
3. 让 Codex 解释失败原因，不直接改代码。
4. 生成最小修复。
5. 运行回归测试并保留修复 Prompt。
6. 总结五阶提示词：澄清、设计、测试、实现、评审。

### 本章产物

- 一个真实 Bug 的复现记录。
- 失败测试和修复后的测试输出。
- 五阶提示词模板。
- Bug 修复前后 diff。

### 建议记录的 Prompt 节点

- 复现问题 Prompt。
- 先写失败测试 Prompt。
- 只解释不修改 Prompt。
- 最小修复 Prompt。
- 回归评审 Prompt。

### 建议记录的 Bug 或偏差

- AI 直接改实现但没有先写测试。
- 测试只覆盖成功路径。
- 修复一个问题引入另一个回归。

### 本章验收

- 能展示测试从红到绿。
- 能说明为什么修复 Prompt 比“帮我修一下”更有效。

4. 用 Skill 检查缺卡、重复打卡和未处理异常。
5. 记录工具调用、权限边界和失败场景。

### 本章产物

- 数据巡检脚本或 MCP 服务。
- 项目 Skill 文件。
- 一次真实巡检输出。
- 工具调用和失败记录。

### 建议记录的 Prompt 节点

- 创建只读巡检工具 Prompt。
- 配置 MCP Prompt。
- 创建考勤 Skill Prompt。
- 使用 Skill 分析异常数据 Prompt。

### 建议记录的 Bug 或偏差

- 工具误改正式数据库。

5. 实现主管审批通过、驳回和异常冲销。
6. 实现员工月报和部门汇总。
7. 完成异常中心和月报页面。
8. 编写固定演示数据脚本。
9. 完成端到端测试和演示彩排。

### 本章产物

- `services/attendance_service.py`。
- `services/exception_service.py`。
- 月报和统计接口。
- 异常中心、月报页面。
- 固定演示数据。
- 完整业务闭环 v1.0。

### 建议记录的 Prompt 节点

- 考勤规则实现 Prompt。
- 异常生成 Prompt。
- 状态机实现 Prompt。
- 月报设计 Prompt。
- 前端异常中心 Prompt。
- 固定演示数据 Prompt。

### 建议记录的 Bug 或偏差

- 日期边界和跨月计算错误。
- 重复核算产生重复异常。

## 第八章：遗留代码重构

### 本章目标

用真实的代码坏味道演示 AI 辅助重构，而不是单独编造一个假项目。

### 本章任务

1. 从现有代码中寻找真实重复：审批状态逻辑、日期规则、错误处理。
2. 先补特征测试，锁定重构前行为。
3. 抽取共享规则和审批服务。
4. 保持接口兼容，完成回归测试。
5. 对比重构前后的复杂度、重复行和测试结果。

### 本章产物

- 重构前快照。
- 特征测试或回归测试。
- 重构 diff。
- 重构前后对比报告。

### 建议记录的 Prompt 节点

- 代码审计 Prompt。
- 重构计划 Prompt。
- 先补测试 Prompt。
- 分批重构 Prompt。
- 回归失败修复 Prompt。

### 建议记录的 Bug 或偏差

- 重构改变接口行为。
- 测试只验证实现细节，阻碍合理重构。
- AI 一次改太多文件，无法定位回归。

### 本章验收

- 重构前后测试结果一致。
- 公共规则不再重复实现。
- 页面和接口行为不变。

## 第九章：多 Agent 协作

### 本章目标

演示多个 Agent 围绕同一项目分工，而不是只让一个 Agent 包办所有工作。

### 本章任务

1. 确认 Git 基线、分支策略和可用的 worktree 工作方式。
2. 划分编码 Agent、测试 Agent、前端 Agent 和评审 Agent。
3. 为每个 Agent 提供有限上下文和明确交付范围。
4. 编码 Agent 负责规则和异常状态机增强。
5. 测试 Agent 负责边界和回归测试。
6. 前端 Agent 负责异常中心和月报界面。
7. 评审 Agent 检查重复打卡、日期边界、事务和状态机。
8. 合并分支或 worktree，处理冲突并人工裁决。
9. 输出最终评审报告。

### 本章产物

- 每个 Agent 的任务 Prompt。
- 分支或 worktree 记录。
- 冲突和重复实现记录。
- 合并后的 v1.2。
- 评审报告。

### 建议记录的 Prompt 节点

- Agent 分工 Prompt。
- 每个 Agent 的输入上下文 Prompt。
- 评审 Agent 找 Bug Prompt。
- 冲突合并和人工裁决 Prompt。

### 建议记录的 Bug 或偏差

- 两个 Agent 重复实现同一逻辑。
- 某个 Agent 超出自己的文件范围。
- 合并时测试失败。
- 不同 Agent 对同一业务规则理解不一致。

### 本章验收

- 至少两个 Agent 产物真实合并。
- 评审 Agent 至少发现一个真实问题。
- 合并后完整测试通过。

## 第十章：自动化与交付

### 本章目标

把前面的开发流程收束成一套可以重复运行的自动化研发助理。

### 本章任务

1. 完善一键验证脚本。
2. 自动重算考勤并生成日报。
3. 自动生成 commit message 和 PR 描述。
4. 增加本地定时任务或 Git Hook 演示。
5. 运行最终完整交付演示。
6. 输出项目交接文档和下一阶段建议。

### 本章产物

- 一键验收脚本。
- 自动日报样例。
- commit/PR 文案样例。
- Hook 或定时任务运行日志。
- 最终交付清单。

### 建议记录的 Prompt 节点

- 一键验证脚本 Prompt。
- 日报生成 Prompt。
- commit/PR 文案 Prompt。
- Hook 配置 Prompt。
- 最终交付评审 Prompt。

### 建议记录的 Bug 或偏差

- 自动化脚本在干净环境不可运行。
- Hook 阻止正常提交。
- 日报统计口径与月报不一致。
- 自动化操作覆盖正式数据库。

### 本章验收

- 一键脚本能在干净测试库跑通。
- 能生成一份可读的日报。
- 能自动生成规范的 commit message 和 PR 描述。
- 最终成品完成一次完整演示。
