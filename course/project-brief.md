# 主案例确认单

## 项目名称

指尖打卡 2.0：考勤异常闭环平台。

## 项目定位

一个轻量但完整的员工考勤系统，重点不是增删改查，而是从原始打卡数据自动生成异常，并完成申诉、审批和月度结算。

## 用户角色

- 员工：打卡、提交请假/加班、查看考勤异常、提交申诉。
- 主管：查看团队考勤、审批请假/加班、处理异常申诉、查看月报。
- 本课程不实现正式登录鉴权，前端提供员工视角和管理员视角切换。

## 核心业务流程

```text
员工打卡
   |
   v
日考勤核算
   |
   +--> 正常
   +--> 请假
   +--> 迟到 / 早退 / 缺卡 / 缺勤
             |
             v
          员工申诉
             |
             v
          主管审批
             |
       +-----+-----+
       |           |
     通过         驳回
       |           |
       v           v
   冲销异常     异常维持
             |
             v
          月度报表
```

## 功能范围

### 必须实现

- 员工新增、查询、修改和离职。
- 上班签到、下班签出。
- 请假申请、审批和日期冲突校验。
- 加班申请、审批。
- 每日考勤自动核算。
- 异常生成、查询、申诉、通过和驳回。
- 员工月度报表和部门月度概览。
- 固定演示数据和演示脚本。
- 自动化测试与一键验证。

### 不做内容

- 不做真实工资核算。
- 不做 GPS、Wi-Fi 或人脸识别。
- 不做复杂排班和多班次。
- 不做正式 JWT 权限系统。
- 不做短信、邮件或企业微信通知。
- 不做云部署和真实线上运维，只在第十章演示自动化交付思路。

## 技术栈

- Python 3.10+。
- Flask 3。
- SQLite 3。
- 原生 HTML、CSS、JavaScript。
- Python 标准库 `unittest`。
- Git 用于阶段快照和重构演示。

## 数据模型

| 表 | 作用 | 关键字段 |
|---|---|---|
| `employees` | 员工主数据 | id, name, department, employee_no, phone, status |
| `checkins` | 原始打卡记录 | employee_id, check_type, check_time, location |
| `leaves` | 请假申请 | leave_type, start_date, end_date, status, approver |
| `overtimes` | 加班申请 | date, hours, status, approver |
| `attendance_days` | 日核算结果 | work_date, first_in, last_out, late_minutes, early_minutes, status |
| `attendance_exceptions` | 异常与申诉 | exception_type, status, appeal_reason, approver |
| `audit_logs` | 操作审计 | action, entity_type, entity_id, operator, detail |

## 默认考勤规则

- 上班时间：09:00。
- 下班时间：18:00。
- 迟到宽限：5 分钟。
- 早退宽限：5 分钟。
- 工作日：周一至周五。
- 已审批全天请假：不生成迟到、早退和缺勤异常。
- 同一天重复签到、重复签出：拒绝。
- 没有签到直接签出：拒绝。
- 缺上班卡、缺下班卡分别生成异常。
- 全天无打卡且无请假：生成缺勤异常。

## 异常状态机

```text
open -> appealed -> approved
                 -> rejected
```

- `open`：系统生成，等待员工处理。
- `appealed`：员工已申诉，等待主管处理。
- `approved`：申诉通过，异常冲销。
- `rejected`：申诉驳回，异常维持。

## 前端页面

- 首页概览：今日应到、已签到、异常数、待审批数。
- 打卡页：选择员工、签到、签出、今日记录。
- 员工管理：员工列表和新增。
- 请假管理：申请、待审批列表、通过和驳回。
- 加班管理：申请、待审批列表、通过和驳回。
- 异常中心：筛选、申诉、审批、状态查看。
- 月度报表：选择员工和月份，查看汇总与每日明细。

## 固定演示数据

演示日期固定，避免课程录制时因日期不同导致结果变化。

| 员工 | 打卡情况 | 业务结果 |
|---|---|---|
| 张三 | 08:55 签到，18:05 签出 | 正常 |
| 李四 | 09:22 签到，17:40 签出 | 迟到 + 早退 |
| 王五 | 09:00 签到，无签出 | 缺下班卡 |
| 赵六 | 无打卡，已审批请假 | 请假，不记缺勤 |
| 孙七 | 无打卡，无请假 | 缺勤 |

演示动作：

1. 重算演示日期。
2. 查看李四的迟到和早退异常。
3. 李四提交申诉。
4. 主管通过申诉，异常冲销。
5. 查看孙七缺勤和赵六请假。
6. 打开月度报表，展示汇总和明细。

## 验收标准

- 启动服务无报错，数据库可自动初始化。
- 固定演示数据可通过脚本一键生成。
- 日核算连续执行两次结果一致。
- 重复签到、重复签出、未签到先签出均返回标准错误。
- 请假、加班、异常状态流转非法时返回标准错误。
- 所有接口返回 `{"code": 200, "message": "...", "data": ...}` 格式。
- 月度报表数据与固定演示数据一致。
- 自动化测试覆盖正常、异常、边界和状态机场景。
- 一键验证脚本可以在干净环境中跑通。
