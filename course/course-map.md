# 课程主线与章节规划

具体每章任务、验收标准和 Prompt/Bug 记录点见 `course/chapter-plan.md`。本文件只负责课程结构和时间分配。

## 一句话定位

用 Codex CLI 从零交付一个可运行的考勤业务系统，并沉淀一套可复用的 AI 工程工作流。

## 三个闭环

1. 业务闭环：打卡 -> 规则判定 -> 异常申诉 -> 主管审批 -> 月度结算。
2. 质量闭环：需求 -> 实现 -> 自动测试 -> 修复 -> 回归验证。
3. Agent 闭环：编码 Agent -> 测试 Agent -> 评审 Agent -> 自动化交付。

## 目标人群

- 有基础编程经验，希望用 AI 提升交付效率的开发者。
- 后端、全栈和业务开发工程师。
- 想理解终端智能体工程化流程的技术负责人。

## 学完能获得什么

- 能用 Codex 从空目录搭建一个完整业务项目。
- 能写出可执行的 AGENTS.md、模块 Prompt 和修复 Prompt。
- 能用测试约束 AI 生成代码，而不是只看页面能否打开。
- 能用多 Agent 分工完成编码、测试和评审。
- 能搭建一套本地自动化交付工作流。

## 第七章拆分

2. 数据模型与数据库设计。
3. 日核算规则。
4. 异常生成。
5. 申诉与审批状态机。
6. 月度报表。
7. 前端异常中心。
8. 固定演示数据与联调。
9. 测试与验收。
10. 阶段复盘。

## 第九、十章保留策略

第九章继续讲多 Agent 协作，但只围绕考勤项目分工，避免泛泛而谈。

- 编码 Agent：规则引擎与异常状态机。
- 测试 Agent：边界用例与回归测试。
- 前端 Agent：异常中心与月报页面。
- 评审 Agent：重复打卡、日期边界和事务一致性检查。
- 最后演示分支合并、冲突处理和评审报告。

第十章继续讲自动化研发助理，但以本地可验证链路为主。

- 一键测试和接口验收。
- 自动重算考勤并生成日报。
- 自动生成 commit message 和 PR 描述。
- 定时任务或 hook 演示。
- 最终完整交付演示。

## 短平快原则

- 理论只讲项目中马上要用的部分。
- 每章开头回顾上一章产物，结尾完成一次验收。
- 演示数据固定，避免日期和时区导致录制结果漂移。
- 不承诺生成几十个接口，重点展示业务闭环和质量闭环。
- 每个技术点都必须能在最终项目中找到落点。
