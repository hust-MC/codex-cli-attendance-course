# 第四章 · DeepSeek 版

> DeepSeek 不读仓库文件，所以「把规范沉淀成文件」这件事对它不成立。
> 替代方案：把 `AGENTS.md` 当成系统提示词贴进去，任务 Prompt 同样可以很短。

## 场景

同一轮「员工离职」需求。给 DeepSeek 的做法是把规范内容整段粘进去，任务描述反而比第三章更短。

## Prompt

```text
以下是我的项目规范，后续所有任务都按它执行：

【技术栈】Python 3.10+、Flask 3、SQLite3，原生 HTML/CSS/JS，不引入 ORM 和前端框架。
【目录】routes/ 只放路由且禁止写 SQL；services/ 放业务规则和 SQL；
models/ 只放数据类和序列化；db.py 只负责连接和建表。
【接口】前缀 /api，统一响应 {"code": 200, "message": "...", "data": ...}，
错误码 400 参数或业务错误、404 资源不存在、500 服务器错误，
列表返回 {"total": n, "items": []}，错误信息用中文。
【数据库】默认 checkin.db，建表和索引幂等，查询用参数化 SQL，
唯一性同时在业务层和数据库层保证。
【代码规范】中文注释，函数名 snake_case，类名 PascalCase，每行不超过 120 字符。

现在执行这个任务：
员工离职不是删除，而是把 status 改成 quit，保留历史打卡记录，
离职后不能打卡也不能提交请假或加班申请。
给出需要改动的文件清单和完整代码。
```

## 录课时注意

- 重点对比：任务描述只有三行，规范化部分占了大半屏。
- 这就是第四章的核心结论：**Prompt 的长度不取决于需求复杂度，取决于你有没有把规则沉淀在别处**。
- Codex 版把规范放在文件里，DeepSeek 版只能放在 Prompt 里，效果一样，成本不同。

## 已知会踩的坑

- 规范一长就容易漏看，DeepSeek 偶尔会漏掉「列表返回 total 和 items」这类细节。
- 贴太长时它会开始压缩内容，可以故意留一条少写的规范，现场看它是否察觉。
