# 第四章 · Codex CLI 版

> 第四章的命题：把长 Prompt 里那些稳定的约束搬进 `AGENTS.md`，任务 Prompt 只留本轮增量。

## 场景

项目根目录还没有 `AGENTS.md`。先让 Codex 把散落在历次 Prompt 里的规范整理成 `AGENTS.md`，再用一个很短的 Prompt 实现新模块，对比效果。

## Prompt

第一步，整理规范：

```text
读一下这个项目，把已经在代码里稳定成立、以后每轮都会复用的规则整理成根目录的 AGENTS.md。

只写这些内容：技术栈与版本约束、目录分层与各目录职责、API 响应格式和错误码、
数据库命名与建表约束、编码风格（注释、命名、行宽）、新增模块要补哪些文件。

不要写：业务规则细节、某一次任务的需求、还没实现的计划。
每条规则后面标一句它对应到哪个文件，方便以后核对。
```

第二步，用短 Prompt 干活：

```text
请阅读并遵守根目录 AGENTS.md。

本轮实现员工离职功能：员工不是被删除，而是 status 改成 quit，
保留历史打卡记录，离职后不能再打卡和提交申请。
改完跑一遍接口自测，把结果给我看。
```

## 录课时注意

- 把两段 Prompt 并排放在屏幕上，观众自己就能看出长度差。
- 第二段 Prompt 里没有任何「请加中文注释」「错误码用 400」——这些规则已经在 `AGENTS.md` 里。
- 故意让它违反一条规范（比如让它临时加个 print），看看它会不会自己被 `AGENTS.md` 拉住。

## 已知会踩的坑

- Codex 可能把 `AGENTS.md` 写成需求文档，堆一堆业务规则进去。
- 它整理规范时会照抄代码现状，包括不该固化的实现细节，要当场挑出来。
