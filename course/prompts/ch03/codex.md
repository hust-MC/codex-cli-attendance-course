# 第三章 · Codex CLI 版

> 第三章还没有 `AGENTS.md`，所以 Prompt 必须自带全部约束。这也正是第四章要解决的问题。

## 场景

第二章的「指尖打卡」已经能建员工、打卡、签出。本轮用一轮 Prompt 生成请假和加班两个模块。

## Prompt

```text
在当前 Flask 项目里新增请假和加班两个模块，沿用已有的 routes / services / models 三层结构。

功能：
1. 请假：新增、列表、详情、审批通过、驳回。
2. 加班：新增、列表、详情、审批通过、驳回。
3. 请假校验：类型只能是事假/病假/年假/调休，开始日期不能晚于结束日期，
   与已审批请假的日期区间不能重叠。
4. 加班校验：时长大于 0 且不超过 24 小时，同一员工同一天只能有一条。
5. 审批状态只有 pending / approved / rejected，且只能从 pending 流转一次，
   重复审批返回 400。

约束：
- 路由层不写 SQL，业务规则放在 services。
- 响应格式 {"code": 200, "message": "...", "data": ...}，错误码 400/404/500。
- 数据库是根目录的 checkin.db，测试时用 CHECKIN_DB_PATH 切换。
- 中文注释，函数名 snake_case，每行不超过 120 字符。

本轮不做日考勤核算、异常生成、申诉和月报。
完成后用 curl 自测一遍，把结果给我看。
```

## 录课时注意

- 让 Codex 先说它准备怎么做，再让它动手。看它知不知道该建几张表。
- 重点看它有没有把「审批只能流转一次」写进 service，而不是只写在路由里。
- 卡住的地方就是素材，不要剪掉。

## 已知会踩的坑

- 它很可能默认把 `DELETE /api/employees/<id>` 写成物理删除，需求里要写清楚是逻辑离职。
- 冲突校验很容易只查「待审批」，要检查它查的是不是已审批。
- 改函数签名时容易漏改调用点，本轮就真实踩到过一次，审批接口直接 500。
