# 第三章 · DeepSeek 版

> DeepSeek 读不到仓库文件，Prompt 必须自带上下文，并要求它分步输出。

## 场景

同一轮需求，给 DeepSeek 用。区别是它拿到的是一段自包含的文本，所以要多交代背景和格式。

## Prompt

```text
你是一位 Python 后端工程师。下面是我的项目现状，请按这个现状继续开发。

项目现状：
- Flask 3 + SQLite，入口 app.py，端口 3000。
- 目录分层：routes/ 只放路由，services/ 放业务和 SQL，models/ 放数据类和序列化。
- 已有接口：/api/health、/api/employees 增删改查、/api/checkins/in、/api/checkins/out。
- 统一响应 {"code": 200, "message": "...", "data": ...}，错误码 400/404/500。
- 中文注释，函数名 snake_case，每行不超过 120 字符。
- 数据库文件是 checkin.db，建表和索引要幂等。

本轮要实现请假和加班两个模块，需求如下：
1. 请假：新增、列表、详情、审批通过、驳回。
2. 加班：新增、列表、详情、审批通过、驳回。
3. 请假校验：类型限事假/病假/年假/调休；开始日期不晚于结束日期；
   与已审批请假区间不重叠。
4. 加班校验：时长 > 0 且 <= 24；同一员工同一天只能一条。
5. 审批状态 pending / approved / rejected，只能从 pending 流转一次。

请按这个顺序回答：
第一步，先用一小段话说明你打算新增哪几张表、哪些文件。
第二步，给出完整代码，按文件分块，代码块之间标注文件名。
第三步，列出你能想到的 5 个边界情况和对应的错误提示文案。

本轮不实现日考勤核算、异常、申诉和月报。
```

## 录课时注意

- 第一步的计划就是最好的教学素材：观众能看出模型有没有真的理解需求。
- 第三步让它自己列边界情况，通常会漏「离职员工不能提交申请」这类，可以现场补进去。
- 对比 Codex 版：这段 Prompt 长了一倍多，但多出来的全是 Codex 由 `AGENTS.md` 兜底的内容。

## 已知会踩的坑

- DeepSeek 容易一次性吐很多代码，缺文件分隔，要强调按文件分块。
- 它可能把审批状态写成中文值，和已有的 `pending/approved/rejected` 不一致。
