# 阶段归档与 Prompt 记录规范

## 核心目标

项目开发不是只产出代码，还要产出可用于录课的完整证据链：

- 哪个阶段做了什么。
- 使用了什么 Prompt。
- Codex 执行了哪些命令。
- 中间出现了什么错误。
- 如何通过 Prompt 修复。
- 最终测试结果和演示效果是什么。

## 阶段划分

| 对应章节 | build-log 目录 | 核心产物 | 录制价值 |
|---|---|---|---|
| 第一章 | `ch01-requirements` | 最终演示、PRD、验收标准 | 先展示终局 |
| 第二章 | `ch02-minimal` | Flask、SQLite、员工、签到签出 | 从空目录起步 |
| 第三章 | `ch03-leaves-overtimes` | 请假、加班、审批 | 一次生成完整模块 |
| 第四章 | `ch04-agents-context` | AGENTS.md、上下文结构 | AI 按规范工作 |
| 第五章 | `ch05-tdd` | 失败测试、修复、回归 | 测试驱动开发 |
| 第六章 | `ch06-mcp-skill` | 数据巡检、MCP、Skill | 工具与项目能力 |
| 第七章 | `ch07-attendance-loop` | 核算、异常、申诉、审批、月报 | 完整业务闭环 |
| 第八章 | `ch08-refactor` | 规则抽取、重复逻辑消除 | AI 辅助重构 |
| 第九章 | `ch09-multi-agent` | 分工、合并、评审 | 团队协作演示 |
| 第十章 | `ch10-automation` | 一键验证、日报、PR 描述 | 自动化研发助理 |

## 每阶段必须归档的内容

```text
build-log/
└── ch07-attendance-loop/
    ├── prompt.md          # 实际使用的完整 Prompt
    ├── context.md         # 提供给 Codex 的上下文和文件范围
    ├── commands.log       # 执行过的关键命令
    ├── output.log         # 终端输出摘要
    ├── errors.log         # 报错与失败信息，保留原始内容
    ├── repair-prompt.md   # 修复时使用的 Prompt
    ├── test.log           # 最终测试结果
    ├── diff.patch         # 本阶段代码变更
    ├── notes.md           # 架构决策、踩坑和讲解要点
    └── screenshots/       # 页面或终端关键截图
```

```markdown

## Codex 输出摘要

## 修复 Prompt

## 最终结果

## 可讲解的工程点

## 录课时建议强调

```

## 录制版与完整版分开保存

- `prompts/`：实际构建项目的完整 Prompt，保留全部上下文和约束。
- `course/prompts/`：录制时使用的精简 Prompt，长度适中、便于现场展示。
- 两者都保留，后续修改课程时可以从完整版重新裁剪。

## 录制素材提取点

每个阶段至少提取四类素材：

1. 结果截图：页面、终端、测试报告或数据库查询结果。
2. 失败瞬间：真实报错或 AI 生成偏差，这是课程最有价值的部分。
3. 修复过程：从报错到修复 Prompt，再到验证通过。
4. 讲解金句：这一阶段为什么这样做，以及真实项目中常见误区。

## 阶段快照规则

- 每个可运行阶段完成后打一个 Git 标签或分支。
- 快照必须包含可启动代码、测试结果和对应 Prompt。
- 录制前验证快照可以独立恢复。
- 失败版本单独保留，不覆盖，用于第八章重构演示。

## 第九章专项记录

- 记录 Agent 分工 Prompt。
- 记录每个 Agent 的输入上下文和输出结果。
- 记录分支或 worktree 的创建与合并命令。
- 记录冲突、重复实现和人工裁决过程。
- 记录最终评审报告。

## 第十章专项记录

- 记录一键验证脚本的生成 Prompt。
- 保存自动化运行日志和日报样例。
- 保存 commit message、PR 描述和最终交付清单。
- 保留一次定时任务或 hook 的完整运行记录。
